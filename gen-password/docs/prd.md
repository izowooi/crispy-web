# 암호 생성 웹앱 — 제품 요구 명세서 (PRD)

**문서 버전:** 1.0
**작성일:** 2026-05-14
**프로젝트 코드명:** password-generator

---

## 1. 개요

### 1.1 한 줄 설명
사용자가 옵션을 조절하면 즉시 강력한 랜덤 암호를 생성하고, 암호 강도를 10단계 시각화(이모지/일러스트)로 보여주는 다국어 웹앱.

### 1.2 핵심 컨셉
- **재미있는 강도 시각화:** 단순 "약/중/강" 표시가 아닌 10단계의 인물 변화 일러스트(빈털 → 전문직)로 암호의 강도를 직관적으로 전달.
- **즉시성:** 옵션 변경 시 자동 재생성, 클립보드 복사 한 번에.
- **다국어:** 5개 언어(한/영/중/일/아랍) 지원, 아랍어 RTL 텍스트.

### 1.3 비목표 (Non-goals)
- 사용자 계정/로그인
- 서버에 암호 저장/전송 (전적으로 클라이언트 사이드 생성)
- 비밀번호 관리(저장소) 기능
- 패스프레이즈/PIN 모드 (이번 버전은 랜덤 문자열만)

---

## 2. 사용자 시나리오

1. 사용자가 사이트에 접속한다.
2. 기본 옵션(길이 6, 소문자+숫자)으로 암호가 즉시 생성되어 표시된다.
3. 강도 시각화는 약한 단계의 인물 이모지를 보여준다.
4. 사용자가 길이 슬라이더를 올리거나 대문자/특수문자 체크박스를 켠다.
5. 옵션 변경 즉시 새 암호가 자동 생성되고, 강도 시각화의 인물도 단계가 올라간다.
6. 사용자가 "복사" 버튼을 클릭하면 암호가 클립보드에 복사되고, 버튼 텍스트가 "복사됨!"으로 바뀌면서 화면에 토스트가 뜬다.
7. 필요 시 "🔄" 새로고침 버튼으로 동일 옵션으로 새 암호를 생성한다.
8. 사용자는 우측 상단에서 언어를 바꾸거나 ☀️/🌙 토글로 다크 모드를 전환할 수 있다.

## 3. 기능 요구사항

### 3.1 암호 생성 엔진
- **암호 종류:** 랜덤 문자열 (영문 대/소문자, 숫자, 특수문자 조합)
- **랜덤성 소스:** `crypto.getRandomValues()` (Web Crypto API)
  - `Math.random()`은 절대 사용 금지 (예측 가능성 때문)
- **균등 분포:** 모듈러 바이어스를 피하기 위해 rejection sampling 또는 그에 준하는 기법 사용
- **최소 1개 문자종 강제:** 사용자가 모든 체크박스를 끄려고 하면 마지막 1개는 disabled 처리

### 3.2 사용자 옵션
| 옵션 | 타입 | 범위/값 | 기본값 |
|------|------|---------|--------|
| 길이 | 슬라이더 + 숫자 입력 | 4 ~ 64 | 6 |
| 대문자(A-Z) | 체크박스 | on/off | off |
| 소문자(a-z) | 체크박스 | on/off | **on** |
| 숫자(0-9) | 체크박스 | on/off | **on** |
| 특수문자 | 체크박스 | on/off | off |

특수문자 셋: `!@#$%^&*()-_=+[]{};:,.<>?/`

### 3.3 암호 강도 시각화 (10단계)

#### 강도 산정: 엔트로피(bits) 기반
- 공식: `entropy = length × log2(charsetSize)`
- charsetSize: 활성화된 문자종 크기의 합
  - 대문자 26, 소문자 26, 숫자 10, 특수문자 26 (위 셋 기준)

#### 임계값 (보안 관례 기반, `STRENGTH_THRESHOLDS` 상수로 분리)
| 단계 | 엔트로피(bit) | 의미 |
|------|---------------|------|
| 1 | < 28 | 매우 약함 (즉시 해킹 가능) |
| 2 | 28 ~ 35 | 약함 |
| 3 | 36 ~ 59 | 보통 약함 |
| 4 | 60 ~ 79 | 보통 |
| 5 | 80 ~ 99 | 양호 |
| 6 | 100 ~ 119 | 강함 |
| 7 | 120 ~ 139 | 매우 강함 |
| 8 | 140 ~ 159 | 우수 |
| 9 | 160 ~ 199 | 탁월 |
| 10 | ≥ 200 | 군사급 |

> 임계값은 `lib/strength.ts`에 상수 배열로 분리하여 향후 손쉬운 조정을 보장한다.

#### 시각화 구성요소
1. **10칸 가로 바**
   - 단계별 그라데이션: 회색(1단계) → 계절감(10단계)으로 자연스럽게 전환
   - 채워진 칸은 색상, 미달성 칸은 옅은 회색
2. **단계별 인물 이모지(플레이스홀더)**
   - 1: 🥲 (빈털)
   - 2: 😪
   - 3: 🙂
   - 4: 😊
   - 5: 😎
   - 6: 🧑‍🎓
   - 7: 🧑‍💼
   - 8: 🧑‍⚖️
   - 9: 🤵
   - 10: 🤴 (전문직/완성형)
3. **일러스트 교체 슬롯**
   - `public/strength/level-1.svg ~ level-10.svg` 빈 SVG 파일 10개를 미리 생성
   - 컴포넌트는 `<img src="/strength/level-N.svg">` 시도 후 onError 시 이모지 fallback
   - 향후 디자이너가 SVG/PNG 파일만 교체하면 자동 반영

### 3.4 액션 버튼
- **복사 버튼:** 클릭 시
  - `navigator.clipboard.writeText()`로 암호 복사
  - 버튼 텍스트 1.5초간 "복사됨!"으로 변경
  - 화면 하단에 토스트 메시지 (자체 구현, 라이브러리 미사용)
- **새로고침 버튼:** 클릭 시 동일 옵션으로 새 암호 생성
- **자동 재생성:** 슬라이더/체크박스 값 변경 시 즉시 재생성

### 3.5 다국어 (i18n)
- **지원 언어:** 한국어(기본), 영어, 중국어(간체), 일본어, 아랍어
- **선택 UI:** 우측 상단 드롭다운 (5개 옵션, 국기 이모지 + 언어명)
- **저장:** localStorage에 선택 저장, 다음 방문 시 자동 적용
- **아랍어 RTL:** 텍스트만 RTL(`dir="rtl"` 또는 CSS `direction: rtl` 텍스트 단위 적용), 레이아웃은 LTR 유지
- **번역 키:** `lib/i18n/<locale>.ts` 파일 5개로 분리

### 3.6 테마
- **자동:** Tailwind `dark:` 변형으로 OS 설정 감지
- **수동 토글:** 우측 상단 ☀️/🌙 이모지 버튼 (텍스트 없이 이모지만)
- **저장:** localStorage에 사용자 선택 저장. 저장값 없을 시 OS 설정 따름.

## 4. 비기능 요구사항

### 4.1 보안
- 모든 암호 생성은 클라이언트(브라우저)에서만 수행
- 서버로 암호 전송 금지
- 암호를 localStorage/sessionStorage/쿠키에 저장 금지
- 생성 이력(history) 기능 없음 (어깨너머 위험 회피)

### 4.2 접근성 (a11y)
- 모든 인터랙티브 요소에 `aria-label`
- 슬라이더는 키보드(←/→) 조작 가능
- 강도 시각화에 `aria-live="polite"`로 스크린리더 안내
- 다크모드 / 라이트모드 모두 WCAG AA 대비

### 4.3 성능
- 페이지 초기 로드 < 1.5s (3G 기준)
- 옵션 변경 → 새 암호 표시 < 50ms

### 4.4 호환성
- 최신 Chrome/Safari/Firefox/Edge 2개 메이저 버전
- iOS Safari, Android Chrome
- IE 미지원

## 5. 기술 스택

| 영역 | 선택 | 비고 |
|------|------|------|
| 프레임워크 | Next.js 14+ (App Router) | `'use client'` 페이지 |
| 언어 | TypeScript | strict 모드 |
| 스타일 | Tailwind CSS | dark: 변형 사용 |
| 패키지 매니저 | npm | `create-next-app` 기본 |
| 랜덤 | Web Crypto API | `crypto.getRandomValues` |
| 클립보드 | Web Clipboard API | `navigator.clipboard` |
| i18n | 자체 구현 (사전 객체) | 라이브러리 없음, 가벼움 |
| 강도 계산 | 자체 구현 | zxcvbn 등 미사용 |

> 랜덤 생성기에 zxcvbn은 부적합 (사전 공격 가정 라이브러리). 직접 만든 암호의 엔트로피 계산이 정확한 길.

## 9. 결정 이력 / 메모

- 길이 기본값을 6+소문자+숫자로 두는 이유:
  - 엔트로피 계산: `6 × log₂(36) ≈ 31.0 bits` → **2단계 착지** (임계값 28~35)
  - 1단계가 아닌 2단계에서 시작하는 의도: 사용자가 위로 올릴 수도 있고, **"이보다 더 약한 단계는 어떻게 생겼지?"** 하고 한두 칸 내려보는 탐색의 재미도 동시에 제공.
  - 12는 단계가 너무 위쪽(8~9)에 시작해서 "성취감"의 출발선을 가져버림. 6은 양방향 탐색이 가능한 지점.
- 강도 임계값을 상수 배열로 분리하는 이유: 일러스트 교체 시 단계의 시각적 균형을 봐가며 임계값을 미세 조정할 가능성이 높음.
- 다크모드 토글에 텍스트 대신 이모지(☀️/🌙) 사용: 다국어 환경에서도 시인성 일관 유지.
- 아랍어는 텍스트만 RTL로 하고 레이아웃은 유지: 암호 자체는 LTR로 읽혀야 하고, 옵션 패널의 좌-우 일관성도 흔들리지 않게.

> 작성일: 2026-03-17
> 버전: 0.1 (초안)

## 1. 서비스 개요

### 1.1 서비스명
**TimeNuts** - 가족이 함께 쓰는 심플한 공유 캘린더

### 1.2 목적
가족 구성원이 각자의 일정을 한눈에 파악하고, 알림을 통해 놓치는 일정 없이 생활할 수 있도록 돕는 공유 캘린더 웹앱

### 1.3 핵심 가치
- **심플함**: 할 일(Todo)과 일정 구분 없이 그냥 일정만. 복잡한 기능 없음
- **가시성**: 구성원별 색상으로 누구의 일정인지 한눈에 파악
- **공유**: 초대 코드(파티)로 가족 그룹을 만들어 함께 사용
- **알림**: 팝업 + 브라우저 푸시 알림으로 중요 일정 놓치지 않기

### 1.4 타깃 사용자
- 가족 단위 (스마트폰 + PC 혼합 환경)
- 아이폰, 안드로이드, PC 웹브라우저에서 모두 접근 가능

## 2. 핵심 기능

### 2.1 그룹(파티) 시스템
- 최초 사용자가 가족 그룹을 생성
- 6자리 초대 코드를 공유하면 가족이 참여 가능
- 한 사용자가 여러 그룹에 속할 수 있음 (추후 확장 고려)
- 그룹 내 구성원 역할: 관리자(그룹 생성자), 일반 멤버

### 2.2 캘린더 뷰
- **월간 뷰(기본)**: 한 달을 한 페이지에 크게 표시 (위젯 스타일)
- **주간 뷰**: 주간 일정 상세 확인
- **일간 뷰**: 당일 시간대별 일정
- 뷰 전환 버튼으로 쉽게 이동

### 2.3 일정 관리
- 일정 생성: 제목, 날짜, 시작/종료 시간, 구성원 지정, 메모
- 일정 수정/삭제
- 반복 일정 (매일/매주/매월/매년) - 선택적
- **할 일(Todo) 구분 없음**: 일정 하나의 타입만 존재

### 2.4 색상 구분
- 구성원마다 고유 색상 지정 (최대 8가지 프리셋 색상)
- 캘린더에서 누구의 일정인지 색상으로 즉시 식별
- 색상 팔레트:
  - 하늘색 (Sky Blue)
  - 연분홍 (Light Pink)
  - 연초록 (Light Green)
  - 연노랑 (Light Yellow)
  - 연보라 (Lavender)
  - 살구색 (Peach)
  - 민트색 (Mint)
  - 연주황 (Light Orange)

### 2.5 알림 시스템
- **브라우저 푸시 알림**: Web Push API 활용
  - 일정 시작 10분 전, 1시간 전 알림
  - 알림 시점은 사용자가 설정 가능
- **인앱 팝업**: 앱을 열고 있을 때 다가오는 일정 팝업 표시
- 알림 설정: 구성원별 ON/OFF 가능

### 2.6 사용자 인증
- 소셜 로그인: 구글, 카카오 (카카오는 추후 추가)
- 이메일/비밀번호 로그인 (기본)
- Supabase Auth 활용

## 4. 데이터베이스 스키마 (Supabase PostgreSQL)

### 4.1 users (Supabase Auth 기본 제공 + 확장)

```sql
-- auth.users 는 Supabase가 관리
-- 아래는 공개 프로필 테이블
CREATE TABLE public.profiles (
  id          UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  avatar_url  TEXT,
  color       TEXT NOT NULL DEFAULT '#7DD3FC', -- 개인 대표 색상
  created_at  TIMESTAMPTZ DEFAULT NOW()
);
```

### 4.2 groups (가족 그룹)

```sql
CREATE TABLE public.groups (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT NOT NULL,           -- 예: "우리 가족"
  invite_code  TEXT UNIQUE NOT NULL,    -- 6자리 초대 코드
  owner_id     UUID REFERENCES auth.users(id),
  created_at   TIMESTAMPTZ DEFAULT NOW()
);
```

### 4.3 group_members (그룹 멤버십)

```sql
CREATE TABLE public.group_members (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id   UUID REFERENCES public.groups(id) ON DELETE CASCADE,
  user_id    UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  role       TEXT NOT NULL DEFAULT 'member', -- 'admin' | 'member'
  joined_at  TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (group_id, user_id)
);
```

### 4.4 events (일정)

```sql
CREATE TABLE public.events (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  group_id     UUID REFERENCES public.groups(id) ON DELETE CASCADE,
  owner_id     UUID REFERENCES auth.users(id) ON DELETE CASCADE, -- 일정 작성자
  title        TEXT NOT NULL,
  description  TEXT,
  start_at     TIMESTAMPTZ NOT NULL,
  end_at       TIMESTAMPTZ NOT NULL,
  all_day      BOOLEAN DEFAULT FALSE,
  color        TEXT,           -- NULL이면 owner의 프로필 색상 사용
  -- 반복 일정 (선택)
  recurrence   TEXT,           -- 'daily' | 'weekly' | 'monthly' | 'yearly' | NULL
  recurrence_end_at TIMESTAMPTZ,
  created_at   TIMESTAMPTZ DEFAULT NOW(),
  updated_at   TIMESTAMPTZ DEFAULT NOW()
);
```

### 4.5 notifications (알림 설정)

```sql
CREATE TABLE public.notification_subscriptions (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  endpoint     TEXT NOT NULL,       -- Web Push endpoint
  p256dh       TEXT NOT NULL,       -- 공개키
  auth         TEXT NOT NULL,       -- 인증 시크릿
  created_at   TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, endpoint)
);
```

### 4.6 Row Level Security (RLS) 전략

- `profiles`: 본인만 수정, 같은 그룹 멤버는 읽기 가능
- `groups`: 그룹 멤버만 읽기 가능, owner만 수정/삭제
- `group_members`: 그룹 멤버만 읽기 가능, admin만 멤버 추가/삭제
- `events`: 그룹 멤버 전체 읽기, 작성자(owner)만 수정/삭제
- `notification_subscriptions`: 본인만 CRUD

## 7. 배포 전략

### 7.1 Cloudflare Pages
- Next.js 앱을 Cloudflare Pages에 배포
- `@cloudflare/next-on-pages` 패키지 사용
- Edge Runtime 활용 (빠른 응답)

### 7.2 API 경계
- **Cloudflare Pages Functions에서 처리**:
  - Supabase 조회/생성/수정/삭제 (CRUD)
  - 사용자 인증 처리
  - 초대 코드 검증
- **Google Cloud Functions (필요 시)**:
  - Web Push 알림 발송 (node-webpush 라이브러리 의존)
  - 반복 일정 자동 생성 (Cron Job)
  - 번들 크기가 Workers 제한(1MB)을 초과할 경우 이관

### 7.3 실시간 동기화
- Supabase Realtime으로 같은 그룹 내 일정 변경 즉시 반영
- 클라이언트 사이드에서 WebSocket 구독

### 7.4 환경 변수
```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
NEXT_PUBLIC_BASE_URL=
VAPID_PUBLIC_KEY=          # Web Push 공개키
VAPID_PRIVATE_KEY=         # Web Push 비공개키
VAPID_SUBJECT=             # mailto: 또는 URL
```

## 8. 보안

- **RLS(Row Level Security)**: 그룹 외부 사용자는 데이터 접근 불가
- **초대 코드**: 6자리 랜덤 코드, 그룹 삭제 시 코드도 무효화
- **HTTPS**: Cloudflare가 자동 제공
- **API Rate Limiting**: Cloudflare 기본 제공
- **인증**: JWT 기반 Supabase Auth 토큰

## 10. 고려사항 및 결정 필요 사항

| 항목 | 옵션 A | 옵션 B | 의견 |
|------|--------|--------|------|
| Supabase 프로젝트 | 기존 프로젝트에 테이블 추가 | 신규 프로젝트 생성 | 기존 프로젝트 사용 예정 |
| 반복 일정 구현 방식 | DB에 개별 저장 | 규칙 저장 후 클라이언트 생성 | Phase 2에서 결정 |
| 알림 발송 주체 | Cloudflare Cron Triggers | Google Cloud Scheduler + GCF | Workers 용량에 따라 결정 |
| 캘린더 라이브러리 | react-big-calendar | 직접 구현 | 직접 구현 선호 (단순함) |
| 구성원 최대 수 | 6명 | 제한 없음 | 가족용이므로 6~8명이면 충분 |

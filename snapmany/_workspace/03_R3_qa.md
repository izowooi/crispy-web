## D. 전체 통합 정합성 (R1~R3 종합 — R3의 핵심 게이트)

### D1. fetch 요청 body 키 ↔ route handler 읽기
- `src/app/page.tsx:136` → `body: JSON.stringify({ image: imageDataUrl, styleId })`
- `src/app/api/generate/route.ts:88-89` → `(body as Record<string, unknown>).image` / `.styleId`
- → **키 이름 `image`/`styleId` 완전 일치.**

### D2. route handler 응답 필드 ↔ page.tsx 응답 처리
- `route.ts` 응답 타입(line 7-8): `{ ok, styleId, imageUrl }` (200) / `{ ok, styleId, error }` (4xx/5xx)
- `route.ts` 실제 반환(line 134/137/141/145 등): 모두 동일 shape
- `page.tsx:138-166` → `json.ok` 분기 → `json.imageUrl` (ok:true) / `json.error` (ok:false) 소비
- → **shape 완전 정합.** `styleId`는 fetch 응답에서 굳이 안 읽지만(클라이언트가 itemId/styleId 보유), 백엔드는 항상 echo함 — 무해.

### D3. STYLES.id 집합 ↔ page.tsx styleId 사용 ↔ route handler 검증
- `page.tsx:18` → `import { STYLES } from "@/config/styles"` — `labelOf()`만 사용. `selectedIds`는 `StylePicker`에서 받음 (StylePicker도 `STYLES` 기반).
- `route.ts` → `isKnownStyleId(STYLE_IDS)` 검증 (R2 backend).
- → **세 경로 모두 동일 `src/config/styles.ts` import** — drift 불가. 자동 정합.

### D4. RC 키 page.tsx 소비 매트릭스
| RC 키 | page.tsx 소비 | 위치 |
|-------|--------------|------|
| `enabled_styles` | ✓ | `StylePicker.enabledStyleIds` (`[...config.enabled_styles]`) |
| `style_order` | ✓ | `StylePicker.styleOrder` (`[...config.style_order]`) |
| `maintenance_mode` | ✓ | 배너 + 생성 버튼 `disabled` |
| `max_upload_size_mb` | ✓ | `UploadPanel.maxSizeBytes` (× 1024 × 1024) |
| `ui_copy.title`/`subtitle`/`generateButton` | ✓ | 헤더 + CTA |
| `default_style_count` | (미사용) | MVP 의도적 미소비 — R3 frontend 보고 §5 명시 |
| `show_beta_styles` | (미사용) | MVP 의도적 미소비 |

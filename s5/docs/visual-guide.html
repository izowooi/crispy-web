삼국지 5 황금판 1.10r을 대상으로 만든 에뮬레이터 s5의 구조를 그림으로 따라갑니다. x86 CPU, Win32 API 고수준 에뮬레이션, 화면·입력·소리 연결, 데이터 팩, 세이브, 배포까지 — 내 게임 에뮬레이터를 만들 때 바로 쓸 수 있는 설계 포인트를 모았습니다.

게임은 포함되어 있지 않습니다. 삼국지 5의 저작권은 KOEI TECMO에 있습니다. 저장소에는 게임 실행 파일·데이터·음원·영상·추출 리소스·스크린샷이 없으며, 실행하려면 본인이 합법적으로 소유한 게임이 필요합니다. 이 페이지의 그림도 모두 구조도이며 게임 화면을 쓰지 않았습니다.
01

전체 구조: 브라우저 하나에 다 들어 있다

서버는 파일만 줍니다. 화면 스트리밍이 아니라, 접속한 기기의 브라우저가 게임 exe를 직접 해석·실행합니다. 메인 스레드는 "모니터·키보드·스피커·디스크", Web Worker는 "PC 본체" 역할입니다.

메인 스레드

입출력 장치

DOM·Canvas·WebAudio·IndexedDB 같은 비동기 브라우저 API를 담당합니다. 사용자의 게임 파일을 검증해 저장합니다.

Worker

PC 본체

x86 명령을 실행하고, 게임이 부르는 Win32 API를 JavaScript로 흉내 냅니다. 메인 스레드를 막지 않습니다.

공유 메모리

버스

SharedArrayBuffer + Atomics로 입력과 동기 파일 I/O를 잇습니다. COOP/COEP 헤더가 필수입니다.

02

부팅 흐름: 폴더 선택부터 타이틀까지

단계를 눌러 보세요. 각 단계가 어느 파일에서 일어나는지, 무엇을 검사하는지 보여 줍니다.

03

엔진: "필요한 만큼만" 흉내 내는 Windows

import 테이블의 DLL 함수 주소를 JS 구현으로 이어지는 hook으로 채웁니다. 게임이 그 주소를 call하면 CPU가 멈추고 JS가 호출 규약에 맞춰 인자를 읽고 EAX를 돌려줍니다.

04

동기 Win32 ↔ 비동기 웹: Atomics로 기다리기

ReadFile은 결과가 나올 때까지 돌아오지 않는 동기 함수지만, IndexedDB는 비동기입니다. Worker가 Atomics.wait로 잠들고, 메인 스레드가 일을 끝낸 뒤 Atomics.notify로 깨웁니다.

필수 헤더

SharedArrayBuffer는 cross-origin isolated 페이지에서만 열립니다.

Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

배포는 deploy/web/_headers, 헤더를 못 거는 로컬 서버는 coi-serviceworker.js가 대신 붙입니다.

알려진 함정

Safari/iPad에서는 엔진이 Invalid file RPC buffer로 멈춥니다. Worker가 받은 버퍼를 SharedArrayBuffer로 인식하지 못하는 WebKit 호환 문제로 보입니다. 엔진을 새로 만든다면 instanceof 대신 Object.prototype.toString 검사나 실제 Atomics 동작 확인을 고려하세요.

05

입력 링 버퍼: 176바이트 고정 레코드

마우스·키보드 이벤트를 고정 크기 레코드로 원형 버퍼에 씁니다. 엔진은 게임이 PeekMessageA를 부를 때만 꺼내 Win32 메시지로 바꾸므로, 입력 처리 시점이 게임 루프와 맞물려 결정적입니다.

button(s)버튼 상태
vk · code · scanCode가상 키
modifiersShift·Ctrl·Alt
delta휠
timetimeOrigin+now

왜 고정 크기?

할당 없이 DataView로 바로 읽고 쓸 수 있고, 잠금 없이 head/tail 인덱스만 Atomics로 갱신하면 됩니다. 용량은 1~65536개.

한글 입력

숨은 textarea로 IME 조합을 받고, 완성 글자를 CP949 2바이트(DBCS)로 바꿔 WM_CHAR 두 개로 넣습니다. 링에 두 칸 여유가 없으면 넣지 않습니다.

06

가상 시계와 속도 배율

게임 시간은 실행한 명령어 수로 흐르고, 벽시계보다 앞서면 쉽니다. 속도 배율은 "벽시계"를 빠르게 흐르게 할 뿐이라 게임 로직은 그대로, 대기만 줄어듭니다. 슬라이더로 예시 구간의 대기 시간을 비교해 보세요.

1x (예시 수치 · 실제 대기는 게임 장면마다 다름)

계산 시간(명령어 실행)은 배율과 무관합니다. 메시지 표시·애니메이션·턴 진행 대기만 1/배율이 됩니다. 2x에서 부팅이 17s → 9.4s로 줄어든 측정이 있습니다.

07

08

SAM5PACK: 단순한 단일 파일 컨테이너

ZIP 대신 "매직 + 길이 + JSON 헤더 + 이어 붙인 데이터". 브라우저에서 Blob.slice만으로 파일별로 꺼낼 수 있고, 항목마다 SHA-256이 있어 검증이 쉽습니다.

"SAM5PACK"0 · 8B magic
headerLength8 · u32 LE
header JSON12 · {version, files[path, role, offset, size, sha256]}
file data …12+headerLength · offset 기준점
executable

게임 exe. SHA-256 고정 — 지원 버전이 아니면 거부.

data

.s5·WAV·MP3·AVI 원본. 필수 .s5 32종 확인, 경로는 NFC 정규화.

glyphs · cursor · module

게임에서 파생된 데이터(원래 runtime.bin). 저작권상 저장소에 없음 — 본인 게임에서 생성.

09

세이브 수명 주기: 세대(generation)를 조심하라

게임을 가져올 때마다 새 세대가 생기고, 이전 세대의 세이브는 지워집니다. 자동 다운로드 어댑터가 "가져온 게임 없음"일 때만 동작하는 이유입니다.

교훈: 데이터 교체 경로가 세이브를 지우는지 먼저 확인하고, 내보내기/가져오기 탈출구는 항상 남겨 두세요.

10

개인 배포와 보안 모델 (Cloudflare)

본인 소유 게임을 본인만 쓰는 개인 배포 예시입니다. 접근 제한은 DRM이 아니며, 공개 URL로 게임을 배포하면 저작권 침해입니다.

우회 URL 차단

workers_dev·preview_urls를 끄고 custom domain만 엽니다.

Fail closed

Access 뒤에 있어도 Worker가 JWT를 다시 검증하고, 설정이 비면 거부합니다.

공유 캐시 금지

응답은 Cache-Control: private. pack 키는 내용 해시라 브라우저엔 immutable.
